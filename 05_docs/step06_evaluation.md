# 06：予測と実績の評価

保存済み予測を商品別の週次実績と照合し、LightGBMと直近7日ベースラインのMAE・WAPEを比較する。

- [4週間の評価一覧](results/four_week_replay_57f6d5b6bf5a43ff856b67dbef4cac2e/report.md)
- [品番別の振り返り・グラフ](results/four_week_replay_57f6d5b6bf5a43ff856b67dbef4cac2e/review_99c547152571470fa585a84a7434903c/report.md)
- [初回週の評価](results/a8d1ac9b-a425-4146-888d-c8cc0227d1d4/report.md)

## 実行方法

対象週の日次CSVを取り込み終えてから、プロジェクト直下で実行する。

```sh
PREDICTION_RUN_ID='<予測コマンドが出力したprediction_run_id>'
docker compose run --rm pipeline python -m evaluation.evaluate \
  --prediction-id "$PREDICTION_RUN_ID" --as-of 2011-06-12
```

`--as-of`は対象週の最終日以降を指定する。日付だけで完了とは判断せず、元CSV・DB明細・日次集計の一致を検査する。
対象週の途中や取り込み不一致では評価を停止する。CSV群の完全性は前提で、CSVとDBから同じ日の記録が両方失われた場合は検知できない。

## 指標

| 指標 | 計算 |
|---|---|
| MAE | 商品別の週合計数量の絶対誤差を平均 |
| WAPE | 絶対誤差の総和 ÷ 実績の総和 |
| ベースライン | 予測時に保存した過去7日合計 |

ベースラインを後日の履歴から計算し直すことはしない。実績0の商品も絶対誤差に含め、商品別WAPEは未定義とする。
全体の実績合計が0なら全体WAPEも未定義である。

## 出力と履歴

評価ごとに`results/評価ID/`を新規作成する。

| ファイル | 内容 |
|---|---|
| report.md | 指標・誤差上位品番・図を含むレポート |
| comparison.csv | 当時の入力・予測・実績・誤差 |
| comparison.png | 予測と実績、誤差上位商品の図 |
| metrics.json | 指標・モデルID・評価日時・入力ハッシュ |

DBは読み取り専用である。実績を予測テーブルへ書き戻さず、既存の予測と評価ファイルも上書きしない。
実績の訂正後は新しい評価IDで記録し、学習時のMLflow指標とは分けて保存する。

## 評価結果の範囲

初回週2011-06-06〜12は、実績合計27,786個、LightGBM WAPE 51.97%、ベースライン63.27%だった。
続く4週を含め、2011-07-10までの5週・500商品週を評価している。

商品選定と分析に同じUCIデータセットを使っているため、これらは既知データによる運用再現である。
将来の精度を保証する結果ではなく、欠品・販促・大口注文の原因も数量比較だけでは判断できない。
