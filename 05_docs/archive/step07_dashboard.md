# 07：需要予測ダッシュボード

## 起動

プロジェクト直下で実行する。

```sh
docker compose -p demandpilot_reorganized --profile tools up -d dashboard
```

http://localhost:8503（当時の参照: `http://localhost:8503`）で開く。停止は`docker compose -p demandpilot_reorganized stop dashboard`である。
MLflowの画面も開く場合は`docker compose -p demandpilot_reorganized --profile tools up -d mlflow`を実行する。
取り込み・学習・予測は別コマンドで行う。

## 画面の使い方

サイドバーで予測週と表示画面を選択する。取り込み後は「データを更新」で読み直す。

| 画面 | 表示内容 |
|---|---|
| 全体評価 | 学習・予測期間、WAPE・MAE、誤差TOP5、週次精度の推移 |
| 商品別分析 | 予測・実績・絶対誤差、過去9週の販売推移、学習時と予測時の特徴量 |
| 実行情報 | モデルID、学習・予測日時、照合状態、予測実行履歴 |

### 全体評価

WAPE・MAEは、それぞれLightGBMとベースラインを横並びで比較する。
改善幅はベースライン−LightGBM。正値が改善、負値が悪化で、単位はWAPEがpp、MAEが販売数量（個）である。

TOP5と品番プルダウンは、絶対誤差順／WAPE順を共通で切り替える。
表の行を選ぶと「詳細を確認する品番」に反映され、「商品別分析へ」で詳細を開ける。
選択は品番で保持し、並び替えや画面切り替えで行番号を引き継がない。
実績0の品番別WAPEは「—」と表示し、WAPE順では末尾に並べる。

精度推移のグラフは、評価済みの週が2週以上あるときに表示す。
各週の最新保存予測を使い、選択週だけは選択した予測実行を表示す。選択週より後の週は表示しない。

### 商品別分析

予測対象週を含む過去9週の週合計実績をSQLで集計する。予測値は保存済みの週だけを点で重ね、対象週を薄い帯で示す。
未完了・記録なしの週は空欄にし、取り込み済み週で対象商品だけ記録がなければ販売0として扱う。
過去週のDB集計だけでは、期間途中の取り込み漏れを独立に判定できない。

特徴量は、同じ品番の学習時の中央値と、予測時に保存した入力値を比較する。
学習CSVを照合できない場合や値がない場合は「未記録」と表示す。

### 実行情報

同じ週の別の予測実行も選択できる。モデルURI・MLflow実行ID・保存学習CSVのハッシュを照合して、学習期間と特徴量を取得する。
学習期間は実際の学習サンプルの基準日範囲であり、元データを読み出した期間ではない。
実績のDB更新日時と予測失敗ログは保存していないため「未記録」である。販売実績の最終記録日とは区別している。

## データと評価

`weekly_forecasts`から保存済み予測と特徴量、`daily_sales`から販売実績、MLflowから学習記録を読む。
対象週の指標は既存の`compare_actuals()`で元CSV・明細・日次集計を照合した後に表示す。不一致・実績不足は「確認待ち」である。
訂正で表示値が変わる場合がある。固定した評価記録はstep06（当時の参照: `step06_evaluation.md`）にある。

DB接続とMLflow SQLiteは読み取り専用、`01_data/storage/`も読み取り専用マウントである。
画面の公開先はローカルの`127.0.0.1:8503`のみである。
