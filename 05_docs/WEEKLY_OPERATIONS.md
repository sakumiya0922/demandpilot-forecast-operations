# 週次モデル運用の再現（TimeSeriesSplit + MLflow）

## 目的

**約半年分でモデルを作り、4週でハイパーパラメータを選定し、独立した4週で最終評価し、その後は毎週推論・評価・再学習判断を行う**という運用サイクルを、2010〜2011年の過去データでオフライン再現します。

これはリアルタイムのスケジューラではありません。**一度のコマンドで歴史を時系列順に再生するシミュレーション**です。元のPostgreSQL DB、従来モデルのRun、Streamlit画面は変更しません。運用履歴はMLflowに記録します。

## 時間軸と判定

| 段階 | 基準日 | 動作 |
|---|---|---|
| 初期学習 | 〜2011-05末を中心とする過去半年 | 日曜の週次サンプルを使用。確定ラベルのみ学習 |
| ハイパーパラメータ検証 | 2011-06-05 / 12 / 19 / 26 | `TimeSeriesSplit(n_splits=4, test_size=1)`を**週単位**に適用。学習可能なラベルは予測基準日以前に確定したもののみ。3候補を同じ4週で評価 |
| テスト | 2011-07-03 / 10 / 17 / 24 | 検証後に選んだハイパーパラメータのモデルを**固定**して評価。テストを使ってハイパーパラメータは再選定しない |
| 運用再現 | 2011-07-31〜実績が確定した最終週 | 毎週モデルで翌週の需要を予測。次週に前週の実績を確認し、WAPEをベースラインと比較 |
| モデル更新 | 悪化が2週連続した翌週の予測前 | その基準日に**ラベルが確定した行**で再学習。ハイパーパラメータは原則固定。モデルバージョン・更新理由を記録 |

* 4週の検証指標は4週分全体のWAPE（絶対誤差合計 ÷ 実績合計）で選定し、同率時はMAEで決定します。
* 「悪化」は同じ週・同じ100品番に対するモデルのWAPEが直近7日数量ベースラインのWAPEを**上回る**ことです。実績合計が0でWAPEが計算不能なら、悪化週と判定しません。
* 最終テストでベースライン未満なら、運用に適用する予測はベースラインへ切り替える仕様です。LightGBMの結果も比較用に記録します。不採用のLightGBMも並行してシャドー評価を行い、2週連続でベースライン以上の精度なら翌週から採用します。再学習した直後はベースラインを使用し、新モデルの週次実績を確認してから再採用を判断します。
* 予測Runには未確定の正解を保存しません。次の基準日に正解が判明してから別の監視Runに記録します。
* 2011年12月9日で実績が終わるため、12月5〜11日の週は評価できません。完全に正解を持つ週までがシミュレーション対象です。
* 対象100品番の選択自体には過去全期間のデータを使っているため、**品番の選択に関する先読みバイアスは残ります**。時系列評価は、固定された100品番内での運用再現です。

## 実行（既存のローカルプロジェクト内）

```bash
cd ~/Projects/demandpilot-reorganized
# 日次データをすでにPostgreSQLに登録している前提
# 一度だけ全期間の学習・評価サンプルを生成する
# すでにweekly_training_full.csvがあるなら作成不要

docker compose -p demandpilot_reorganized --profile tools run --rm pipeline \
  python -m training.training_data \
  --start 2010-12-01 --end 2011-12-09 \
  --output 01_data/storage/training/weekly_training_full.csv

# 4週のCV探索 → 4週の固定モデルテスト → 週次推論 → 精度監視と必要時再学習
docker compose -p demandpilot_reorganized --profile tools run --rm pipeline \
  python -m training.weekly_operations
```

注意：`weekly_training_full.csv`が既にある場合、学習データ生成コマンドは上書きを拒否します。削除ではなく、別名で作成するか既存ファイルを使用してください。

## MLflowの記録

`http://localhost:5002` の `demandpilot-weekly-operations` 実験です。

- 親Run `weekly-model-lifecycle`：入力CSVハッシュ、選択候補、期間、テスト集計、週次推論全体CSV、再学習イベント履歴、ソース
- 子Run `tuning-candidate-*`：ハイパーパラメータ候補と4週合計の検証結果
- 孫Run `cv-fold-*`：各検証週のトレーニング行数・最終ラベル日・WAPE/MAE・予測CSV
- 子Run `test-*`：固定モデルの4週テストの評価
- 子Run `forecast-*`：予測時点のモデルバージョン、予測CSV、予測数量（正解は含めない）
- 子Run `monitor-*`：**翌週になってから**前週のWAPE/MAEを記録。連続悪化時は再学習モデルの保存と更新履歴を記録

**未実施**：過去週の運用リプレイ結果をPostgreSQLの`weekly_forecasts`へ書き戻すこと、Streamlitでの運用モデル切替、定期ジョブ、自動採用の可否判定。これらはMLflowへの再現履歴の次段階です。
